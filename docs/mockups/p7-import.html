Where these folders come from

The server only reads from its import directory: /data/import (env IMPORT_DIR; dev default ./.data/import). In Docker, mount your corpus there — e.g. -v ~/recipes:/data/import — or copy a folder in, then Refresh. Detection looks one level deep: the import directory itself or any immediate child can be a source root. Formats are auto-detected; nothing is imported until you press Import.

2 · Import running — the chosen row pins with live progress

POST /api/v1/import {path} starts a background job; the pane polls GET /api/v1/import/jobs/{id} every ~2s (same pattern as the Nutrition tab's bulk compute). Only one import runs at a time — starting another returns 409, so the other rows' Import buttons disable while a job is live. Warnings count up in the stats line as they accumulate.

3 · Terminal states — done, done with legacy warnings, failed

The finished job replaces the progress bar with a one-line summary in the pinned row's place; the counts come straight from the job envelope (total, imported, updated, skipped, failed). "See warnings" expands the job's per-file log — mono, scroll-capped at 200px, exactly the Nutrition tab's job-log treatment. Warning filenames below are real corpus files.
