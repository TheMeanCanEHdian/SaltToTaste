Tag input — redesigned around FAutocomplete

The tag field moves off a hand-rolled RawAutocomplete and onto Forui's FAutocomplete. That kills two confirmed bugs and drops a bespoke overlay widget — but FAutocomplete is a bordered field, so the chips can no longer sit inside it. This is the layout that follows.

Real recipe: 0879-easy-caramel-cake.yaml · real tag dessert (214 recipes) · real tokens from salt_theme.dart · the app is light-themed by design, so the frames stay light in both page themes

Why the layout has to change. Today the chips and the text cursor live in one bordered box. FAutocomplete renders its own bordered field, so keeping that shape would nest a border inside a border. Putting the chips above the field is the honest Forui layout — and it reads better once a recipe has more than a couple of tags, since the chips wrap freely instead of shoving the cursor onto a second line.

The states that matter

Each of these is a bug the current field gets wrong. Enter currently commits the raw text, so typing “des” and pressing Enter mints a junk tag des instead of taking dessert — and the suggestion list can’t be reached by keyboard at all.

One decision inside this. When the typed text matches an existing tag, Enter takes the match and creating a near-identical tag needs the explicit Create row. That is the whole point — the vocabulary is shared across 1,198 recipes, and des/desserts/Dessert next to dessert is the failure mode worth designing against. If you would rather Enter always create, say so and I’ll flip it.
