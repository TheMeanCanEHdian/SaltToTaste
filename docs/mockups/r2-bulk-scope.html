3 · One decision for you — where do the counts come from?
The counts on the segments need a server call the API does not have yet. Today POST /nutrition/bulk returns total only after starting the job. Showing “Stale 3” before you click means a read-only preview:
OptionWhat it needsWhat you see
A · Preview endpoint (drawn above)GET /api/v1/nutrition/bulk/counts → {missing, stale, all}. Same ~110–190 ms hash pass the sweep already does; admin-only; runs once when the tab opens and after each job.Counts on every segment, button says exactly what it will do, Stale=0 disables itself.
B · No previewNothing new server-side.Segments have no counts; button says “Compute missing” / “Recompute stale” / “Recompute all”; the number appears on the 202 and in the progress line. A stale sweep that finds nothing shows the green banner after you click.
My recommendation is A: the whole point of Stale is to spend budget only where it is needed, and the count is what tells you whether that is 3 recipes or 300 before you commit to it. The endpoint is small and reuses bulkScopeIds unchanged.
